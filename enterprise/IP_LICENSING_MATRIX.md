# CMB IP and Licensing Matrix

**Purpose:** clarify repository boundaries for enterprise diligence.  
**Status:** project documentation, not legal advice.

## Current repository split

| Material | Current treatment |
|---|---|
| source code | Apache License 2.0 unless a file states otherwise |
| tests and schemas | Apache-2.0 unless stated otherwise |
| implementation documentation | Apache-2.0 unless stated otherwise |
| manifestos / poetry / narrative corpus | rights reserved unless stated otherwise |
| original CMB / D.N.A. / FGC expressive material | governed by `CONTENT_LICENSE.md` |
| third-party names, symbols, standards, and works | remain subject to their own rights |

## Enterprise implication

Apache-2.0 software already grants broad rights to use, modify, reproduce, and distribute covered software subject to its terms. Therefore CMB should **not** promise sector exclusivity over rights already granted to the public in released Apache-2.0 code.

Possible enterprise agreements can instead cover distinct value:

- hosted or managed services;
- enterprise-only integration modules;
- support and SLA commitments;
- implementation services;
- certification criteria and audit services;
- controlled trademarks / trust marks if properly established;
- private deployment configurations;
- organization-specific policy packs; and
- governance participation defined by contract.

## Attribution and provenance

Cryptographic provenance can preserve evidence that a specific signed artifact, receipt, or release traces to a given key or repository state.

It cannot independently decide legal authorship, copyright ownership, trademark rights, patent rights, or historical priority.

```text
HASH != AUTHORSHIP
SIGNATURE != ORIGINALITY
TIMESTAMP != OWNERSHIP
LICENSE != TRADEMARK_RIGHT
```

## Co-stewardship principle

A future enterprise design partner may participate in implementation, testing, governance proposals, interoperability, or standards work without acquiring unilateral authority over the creator's literary corpus or over public Apache-licensed rights already granted to others.

Any future trademark, certification, foundation, nonprofit, trust, or commercial-license structure should be documented separately after appropriate professional legal review.
