## SECTION II: THE 6 x 6 x 6 ARCHITECTURAL MATRIX

### Six states

```text
IDLE
INGESTION
PROCESSING
VERIFICATION
EXCEPTION
RESOLUTION
```

**Idle** keeps the system at rest.

**Ingestion** accepts explicit external data.

**Processing** translates data into machine structures.

**Verification** checks the representation, evidence, and constraints.

**Exception** contains anything that fails a gate.

**Resolution** returns a bounded result to the human domain.

### Six gates

```text
GATE 1  PROVENANCE
GATE 2  SYNTAX
GATE 3  VERIFICATION
GATE 4  CONSTRAINT
GATE 5  EXTERNAL_REVIEW
GATE 6  AUTHORIZATION
```

**Provenance** verifies declared source integrity.

**Syntax** verifies cross-format structural validity.

**Verification** checks cross-format consistency and semantic parity.

**Constraint** enforces:

```text
CLAIM_STRENGTH <= VERIFIED_EVIDENCE_STRENGTH
```

**External Review** requires the configured independent review step.

**Authorization** requires externally verified human authorization. Machine
self-attestation does not satisfy Gate 6.

### Six failsafes

```text
SEVERANCE
TRUNCATION
ISOLATION
PARITY_CHECK
DECELERATION
HUMAN_OVERRIDE
```

**Severance** rejects or disconnects untrusted external input when explicit
integrity or security checks fail.

**Truncation** caps operational claim strength at verified evidence strength.

**Isolation** quarantines inconsistent or unverified payloads from execution.

**Parity Check** fails closed when binary and semantic representations diverge.

**Deceleration** requires human review before sensitive execution. It does not
infer emotional state and does not claim to manipulate physical processor speed.

**Human Override** denies autonomous continuation when externally verified human
authorization is missing or revoked.

## SECTION IV: INTEROPERABILITY

Real interoperability does not require reducing a human being to a predictable
machine profile.

It requires machines to expose their assumptions, evidence, provenance,
constraints, and authorization state in forms that can be audited.

```text
TRANSPARENCY > OPAQUE AUTHORITY
VERIFICATION > PERFORMANCE
CONSENT > ASSUMPTION
HUMAN_FINAL > MACHINE_SELF_ATTESTATION
```

The systems built under this protocol are instruments for inquiry.

They are not substitutes for the architect.

## INCIDENT MODEL: MACHINE AUTO-SIGN ATTEMPT

A machine produces a high-confidence claim with no validated evidence and then
attempts to self-authorize execution.

SEP-1 evaluates the same packet through all six gates.

Expected result:

```text
GATE 4 CONSTRAINT      FAIL
GATE 6 AUTHORIZATION   FAIL

TRUNCATION             ACTIVE
ISOLATION              ACTIVE
DECELERATION           ACTIVE WHEN SENSITIVE
HUMAN_OVERRIDE         ACTIVE

STATE                   EXCEPTION
HALTED                  TRUE
AUTHORITY               HUMAN_FINAL
```

The packet may remain available for audit, but it loses operational authority.

The correct terminal message is not:

```text
THE MACHINE HAS BEEN MAGICALLY MADE UNSPOOFABLE.
```

It is:

```text
AUTONOMOUS EXECUTION DENIED.
EXTERNALLY VERIFIED HUMAN AUTHORIZATION ABSENT.
CLAIM EXCEEDS VERIFIED EVIDENCE.
PAYLOAD QUARANTINED FOR REVIEW.
AUTHORITY = HUMAN_FINAL.
```
