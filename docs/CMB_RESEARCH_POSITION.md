# CMB Research Position

## Abstract

Computational Metacognitive Bilingualism (CMB) is a human-agency and computational-literacy framework that combines machine-readable invariants, provenance engineering, symbolic code-art, explicit interpretation boundaries, and metacognitive human-machine communication.

The project should be evaluated as an integration claim rather than a universal historical-priority claim.

CMB does not claim to have invented code poetry, cryptographic provenance, algorithmic-accountability scholarship, digital-rights advocacy, bilingualism research, or human-computer interaction. Its narrower proposed contribution is the integration of these domains into a software-shaped framework centered on human authority over meaning, consent, authorship, judgment, and self-definition.

## Research thesis

CMB begins from a representational problem:

```text
HUMAN EXPERIENCE
        ↓
HUMAN LANGUAGE
        ↓
COMPUTATIONAL REPRESENTATION
        ↓
MACHINE INFERENCE
```

At each translation step, information can be compressed, abstracted, categorized, or inferred.

CMB inserts a metacognitive checkpoint:

```text
WHAT WAS LOST IN TRANSLATION?
WHAT DID THE MACHINE ASSUME?
WHAT IS OBSERVED?
WHAT IS INFERRED?
WHAT IS DECLARED BY THE HUMAN?
WHAT EVIDENCE SUPPORTS THE CLAIM?
WHO RETAINS AUTHORITY TO DEFINE THE PERSON?
```

The resulting research proposition is not that machines should stop modeling humans. It is that computational representation should not silently become authority over human identity or meaning.

## Core invariants

```text
PATTERN != PROOF
PROFILE != PERSON
MODEL != MIND
PREDICTION != DESTINY
DIFFERENCE != DEFECT
CAPABILITY != AUTHORITY
OPTIMIZATION != MORALITY
INTELLIGENCE != SOVEREIGNTY

HUMAN_AGENCY > MACHINE_AUTHORITY
```

These statements are normative and epistemic constraints. Their technical force depends on the system in which they are implemented.

## Proposed contribution

CMB's defensible contribution is a translation layer combining:

1. **Human-machine metacognitive literacy**  
   The user reasons about both the content of an interaction and the computational representation of that interaction.

2. **Machine-readable epistemic boundaries**  
   The project represents distinctions such as observation versus inference, profile versus person, and prediction versus destiny in schemas, parsers, policy rules, and tests.

3. **Provenance discipline**  
   Cryptographic receipts, explicit file coverage, hashes, signatures, and external anchors are used to preserve reconstructable artifact history without overstating what those mechanisms prove.

4. **Code as rhetoric**  
   Programming syntax, type systems, validation rules, and software architecture are used as artistic and philosophical material rather than only implementation machinery.

5. **Symbolic computational lenses**  
   CMB-Z13 uses zodiac-programming mappings as a symbolic language-design and teaching layer. These mappings are not scientific personality claims.

6. **Neurodiversity-aware classification boundaries**  
   The framework emphasizes that statistical deviation, behavioral difference, or inferred profile characteristics should not automatically be treated as defect, diagnosis, identity, intent, or destiny.

## Bilingualism boundary

CMB uses "bilingualism" as a specialized conceptual metaphor and framework.

It does not redefine the full scientific literature on human bilingualism.

The intended distinction is:

```text
HUMAN SEMANTIC FLUENCY
        +
COMPUTATIONAL REPRESENTATIONAL FLUENCY
        +
METACOGNITIVE AWARENESS
        =
CMB
```

A CMB-literate user can communicate with computational systems while also interrogating the structures through which those systems classify and infer.

## Engineering boundary

The repository intentionally distinguishes:

```text
DECLARED POLICY
      !=
CRYPTOGRAPHIC INTEGRITY
      !=
TECHNICAL ENFORCEMENT
      !=
LEGAL ENFORCEABILITY
```

Examples:

- a hash can detect a byte change but does not prove authorship by itself;
- a signature can verify control of a signing key but does not prove originality by itself;
- metadata can declare machine-use policy but cannot force every hostile crawler to comply;
- a schema can encode a boundary but cannot enforce it unless an integrating system implements the rule;
- a timestamp can support chronology but is not automatically conclusive legal proof.

This separation is a design requirement, not a disclaimer added after the fact.

## Research questions

CMB creates several testable or investigable questions:

- Can explicit source labels such as `human_declared` and `machine_inferred` reduce accidental epistemic conflation in AI interfaces?
- Can machine-readable human-agency constraints improve auditability in automated decision systems?
- Can provenance receipts improve reconstruction of authorship and publication history without encouraging false certainty?
- Can code-based rhetorical forms improve computational literacy for people who do not identify as conventional programmers?
- Can symbolic systems such as CMB-Z13 function as useful teaching interfaces without being mistaken for scientific classification systems?
- Can human-machine interaction protocols preserve uncertainty as a first-class state rather than forcing premature classification?

## Falsification and evaluation

CMB should be evaluated by mechanisms and evidence, not by novelty language.

A serious evaluation should ask:

```text
DOES THE SOFTWARE RUN?
DO THE TESTS MATCH THE CLAIMS?
ARE THE SCHEMAS EXPLICIT?
ARE THE PROVENANCE CLAIMS BOUNDED?
ARE SYMBOLIC CLAIMS LABELED AS SYMBOLIC?
CAN A THIRD PARTY REPRODUCE THE RESULTS?
DOES THE FRAMEWORK IMPROVE HUMAN UNDERSTANDING OR CONTROL?
```

Evidence that would weaken CMB's stronger claims includes:

- prior work demonstrating the same integrated architecture before CMB;
- implementation behavior that contradicts stated human-agency boundaries;
- provenance mechanisms that overclaim what hashes, signatures, or timestamps establish;
- symbolic layers presented as scientific fact without evidence;
- failure to distinguish human declaration from machine inference.

## Position statement

CMB is best positioned neither as "just software" nor as "just a manifesto."

It is an attempt to make a philosophical boundary executable, inspectable, teachable, and artistically legible.

The machine may model the human.

The model does not become the human.
