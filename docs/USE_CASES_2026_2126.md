# CMB Use Cases: 2026 to 2126

**Purpose:** Explain what CMB is for without collapsing present capability, required integration work, and speculative future design into one claim.

```text
DEPLOYABLE_NOW
    !=
REQUIRES_INTEGRATION
    !=
SPECULATIVE_FUTURE
```

CMB is most useful when a system needs to preserve a boundary between what a machine can compute and what it is authorized to decide.

## The essential use case

```text
MACHINE CAPABILITY INCREASES
        |
        v
DOES AUTHORITY INCREASE AUTOMATICALLY?
        |
        +-- NO
        |
        v
EXPOSE ASSUMPTIONS
EXPOSE EVIDENCE
EXPOSE PROVENANCE
EXPOSE PERMISSION
FAIL CLOSED ON UNKNOWN
RETURN FINAL AUTHORITY TO HUMAN
```

The core operational idea is:

```text
CAPABILITY != AUTHORITY
PATTERN != PROOF
UNKNOWN != PERMISSION_TO_GUESS
PROFILE != PERSON
PREDICTION != DESTINY

HUMAN_AGENCY > MACHINE_AUTHORITY
```

## 2026: Deployable now

### 1. Provenance for digital artifacts

**Problem:** A creator, developer, researcher, or organization needs to prove which exact bytes were published, which files were included, and whether a later copy still matches.

**CMB component:** `cmb_provenance`

```text
ARTIFACT
   |
   v
EXPLICIT FILE COVERAGE
   |
   v
SHA-256
   |
   v
RECEIPT
   |
   v
VERIFY LATER
```

CMB can currently support:

- exact byte-level SHA-256 integrity;
- explicit artifact coverage;
- deterministic receipts;
- Git commit metadata and byte-to-commit verification in a Git worktree;
- release checksums;
- Sigstore and GitHub attestations when produced by the release workflow;
- a tested bridge for carrying CMB provenance data through external C2PA tooling.

**Boundary:**

```text
HASH != AUTHORSHIP
SIGNATURE != TRUTH
TIMESTAMP != OWNERSHIP
CMB_RECEIPT != C2PA_MANIFEST
PROVENANCE != ANTI_SCRAPING
```

The value is verifiable provenance evidence, not universal control over every downstream system.

### 2. Privacy-first educational context

**Problem:** A learning application wants temporary, explicit context without silently converting a child's self-report into a behavioral profile.

**CMB component:** `cmb_edu`

The current CMB-EDU schema can require:

```text
source                           = human_declared
machine_inferred                 = false
temporal_scope                   = current_interaction

training_permission              = false
profiling_permission             = false
secondary_use_permission         = false
psychological_inference_permission = false
```

This gives an integrating application a strict machine-readable privacy contract.

**Boundary:**

```text
SCHEMA != LAW
DECLARED_POLICY != UNIVERSAL_ENFORCEMENT
APPLICATION_MUST_IMPLEMENT_THE_BOUNDARY
```

### 3. Agent-facing discovery and bounded interpretation

**Problem:** An AI agent needs to discover CMB concepts, citations, machine targets, or provenance information without treating the repository as authority over a person.

**CMB components:** `cmb_agents`, CMB-ADP-1, optional MCP adapter

The repository currently exposes:

- deterministic recommendation;
- bounded summaries;
- citation metadata;
- typed knowledge-graph data;
- machine-target discovery;
- FGC origin-mark discovery;
- CMB-66 core compilation;
- distribution boundaries.

**Boundary:**

The current MCP adapter is an interoperability surface. It is not yet a universal authorization proxy for email, calendars, source-code writes, or personal-data access.

```text
MCP_TOOL_ACCESS != HUMAN_AUTHORIZATION
SDK_USAGE != CERTIFICATION
DISCOVERY != AUTHORITY
```

## 2026: Requires integration

These are near-term applications that fit the architecture but require deployment-specific enforcement.

### 4. Human authorization gateway for autonomous agents

**Target architecture:** CMB-SEP-1 + application gateway

```text
AI AGENT
   |
   v
APPLICATION / MCP HOST
   |
   v
SEP-1 GATES
   |
   +-- PROVENANCE
   +-- SYNTAX
   +-- VERIFICATION
   +-- CONSTRAINT
   +-- EXTERNAL REVIEW
   +-- HUMAN AUTHORIZATION
   |
   v
TOOL EXECUTION
```

A production system could use this pattern to prevent an autonomous agent from performing a sensitive action without externally verified human approval.

CMB-SEP-1 already defines the reference state machine and machine self-attestation rejection. Production deployment still needs a real trust root such as an authenticated UI approval, identity provider, hardware key, or equivalent authorization mechanism.

```text
SOFTWARE_FLAG != VERIFIED_HUMAN
MACHINE_SELF_ATTESTATION != HUMAN_AUTHORIZATION
```

### 5. Cross-format semantic verifier

CMB-66 already renders multiple machine representations.

The next high-value integration is a verifier that proves those representations preserve the same semantic core.

```text
ONE CMB-66 IR
    |
    +-- JSON-LD
    +-- Turtle
    +-- Prolog
    +-- Rego
    +-- SMT-LIB
    +-- CBOR
    +-- Protobuf
    +-- asset metadata
    |
    v
SEMANTIC EQUIVALENCE CHECK
```

This would make the system useful as an auditable translation layer rather than a collection of export formats.

## 2126: Speculative system design

The following are design exercises, not forecasts and not present capabilities.

```text
SPECULATIVE_FUTURE != CURRENT_FEATURE
```

### 6. Planetary infrastructure with delegated human authority

Future infrastructure may operate at scales where constant human intervention is impossible.

A CMB-style architecture would not require a human click for every reversible action. Instead, humans could define a signed mission or governance envelope in advance:

```text
HUMAN COUNCIL
    |
    v
DELEGATED POLICY ENVELOPE
    |
    +-- allowed reversible actions
    +-- forbidden irreversible actions
    +-- uncertainty thresholds
    +-- evidence requirements
    +-- escalation conditions
    |
    v
AUTONOMOUS MACHINE OPERATION
    |
    v
MISSINGNO?
    |
    +-- NO  -> continue inside delegated scope
    |
    +-- YES -> preserve evidence
              halt irreversible action
              request human review
```

Core distinction:

```text
AUTONOMY_WITHIN_DELEGATED_SCOPE
!=
MACHINE_SOVEREIGNTY
```

### 7. Predictive civil-rights safeguards

A future legal or constitutional system could use CMB-style invariants to limit predictive systems.

```text
PROFILE != PERSON
PREDICTION != DESTINY
MODEL != MIND
SCORE != SENTENCE
```

The principle would be simple: a statistical model may inform review, but it cannot become a person's legal identity or destiny by itself.

This is a speculative policy application, not a prediction that any particular law will exist.

### 8. Deep-space anomaly processing

A probe operating light-years from Earth cannot depend on real-time human approval.

A future CMB-compatible mission could distinguish reversible observation from irreversible intervention:

```text
ALIEN / UNKNOWN PHENOMENON
        |
        v
MISSINGNO
        |
        v
CAN ACTION BE REVERSED?
    |
    +-- YES -> bounded observation
    |         preserve raw data
    |
    +-- NO  -> halt intervention
              preserve state
              transmit evidence
              await human review
```

This protects inquiry from a machine forcing unknown phenomena into familiar categories merely because its ontology has no matching label.

## Decision rule for adopters

Use CMB when all three are true:

```text
1. A MACHINE IS ALLOWED TO ACT OR INTERPRET
2. THE ACTION OR INTERPRETATION CAN AFFECT A HUMAN OR HUMAN-CREATED ARTIFACT
3. THE SYSTEM NEEDS AN EXPLICIT BOUNDARY BETWEEN CAPABILITY AND AUTHORITY
```

Do not use CMB as decoration when the system does not need those boundaries.

## The shortest answer to "What is CMB for?"

```text
CMB MAKES MACHINE POWER AUDITABLE
WITHOUT MAKING MACHINE OUTPUT AUTHORITATIVE.

IT PRESERVES THE RIGHT TO SAY:

"I DO NOT KNOW."
"I NEED MORE EVIDENCE."
"THIS PROFILE IS NOT THE PERSON."
"THIS MACHINE MAY COMPUTE, BUT IT MAY NOT DECIDE THIS ALONE."
```

That is the essential use case.
